# 框架选择：什么需要更新，什么值得学习

最终推荐是**先保证工具观察有效，再选择重算粒度，最后诊断是否需要参数更新**。这三个决策解决不同问题，不能由一个“触发 Agent 重训练”的按钮代替。

## 从问题到机制

数据库的变化单位是行；用户关心的是结论；模型消费的是提示中的工具观察。三者不一一对应。新增一个此前不存在的规则会改变旧答案，尽管旧引用全部还在；反过来，无关行变化可能不改变任何公开观察。

因此维护两个图：业务实体/约束图表达知识，执行依赖图表达某次计算实际读取了什么。RAG 工具提供两者之间的接口：固定候选域、完整性状态、精确公开输出，以及保守覆盖插入/移入/移出/删除的查询范围。空查询同样有范围依赖。

给定一个完整更新批次，先固定不可变快照，然后沿被请求根的旧读取顺序验证。遇到首个改变的前驱就重跑当前节点，重新发现分支；输出没变可以阻止消费者重算，但当前节点的新读集仍必须替换。这个机制继承经典增量计算，不声称是新的通用图算法。

## 为什么默认选择粗范围

如果所有查询已共享等值索引，重查一个项目的成本可能很低。精细谓词额外付出的事件匹配、旧/新成员检查和依赖维护，未必能收回。2,400 行实测中，coarse 在低变化、重复请求的四类负载中累计约 44–48 ms，全量约 104–108 ms；但高扇出时 coarse 约 677 ms，full 约 625 ms，predicate 约 1,483 ms。

所以默认 `coarse`，保留 `full`。`adaptive` 只在固定事件密度阈值上选择两种正确动作，不用概率宣布旧答案有效。其 .25 阈值是开发期选定的启发式，不是最优解；低复用场景没有稳定收益。所有数字是内存更新内核的墙钟微基准，包含维护成本，不能当作模型问答端到端加速。

更一般地，若验证成本为 k，验证后保持不变的概率为 p，直接重算成本为 r，在失败后仍需完整重算的简化条件下，先验证只在 k < p·r 时划算。估计可以错，结果有效性检查不能省。共享子图、批处理和验证结果复用会改变这个模型，首版没有求解全局最优调度问题。

## 三个时标，不是每次写库都训练

| 时标 | 触发条件 | 具体动作 | 不成立的推断 |
|---|---|---|---|
| 事务发布 | 完整批次到达，索引就绪 | CAS 提交、outbox、固定快照 | 数据库已写入不代表每个外部索引都已更新 |
| 请求验证 | 用户请求，旧观察可能受影响 | 范围检查、必要重算、相等截断、当前绑定 | 旧行未变不代表没有新规则 |
| 离线学习 | 当前充分证据下仍有稳定行为错误 | 归因、重标样例、冻结 manifest、同证据 SFT 对照 | 更新训练文件不代表旧 adapter 已遗忘 |

把事实变化留在可撤回、可审核的外部知识中；把有重复证据支持的工具行为适配作为 SFT 候选。没有当前证据、缺少环境、数据不完整或尚未发布，先修数据与流程，训练不能补足这些条件。

## 模型失败怎样改变设计

冻结行为 adapter 在短状态 test 上通过 32/32，但未见条件组合只有 24/32，失败集中在“过期冲突”与“未发布且缺环境/缺观察”的优先级。它表明拟合单一条件不等于学会组合规则。规则基线可以完整执行这个闭合合同，因此没有证据支持让模型取代它。

真实长证据 demo 又发现复制负担：版本值大多正确，却漏状态字段并写坏 JSON。接口对照因此拆成三臂：完整输入输出；保留完整事实输入但只输出绑定引用；压缩输入且输出同样引用。第二臂控制了事实输入，第三臂另外改变输入，不能把二者的收益混成增量算法效果。

绑定引用只是一个闭合传输接口：模型选择当前被提供的观察句柄，宿主检查请求、快照、工具配置和完整结果摘要，再展开。哈希不是事实证明，展开的包版本不是模型自己生成的知识；旧引用不能自动升级成新答案。独立枚举 oracle 校验的是展开后的领域约束。

## 当前结论如何被推翻

- 发现未覆盖输入或缺失更新事件：退回完整快照重算；不能继续宣称精确复用。
- 在目标规模上全量更快：选 full，保留原实验。细粒度只在真实查询成本支持时重开。
- 自由文本/向量检索不能给出完整范围：最多保证相对工具返回值的重跑一致；另外评估召回，不继承有限精确检索保证。
- 模型在新组合上不可靠：保留显式阻断和规则主路径；不能用宿主纠错后的输出计算模型成功率。
- 下一阶段要主张论文创新：先全文复现最接近的增量计算和动态 RAG 工作，再设计能区分机制的实验；仓库组合和更换底座本身不够。

这是一套有范围条件、有成本证据的框架选择；不是对任意数据库、任意 Agent、任意模型都最优的结论。原始数据和各层指标见 [结果页](results.md)。

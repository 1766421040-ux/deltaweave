# DeltaWeave：可证伪评测设计

状态：2026-10-28 保留的早期建议协议，不是最终执行清单。本文数字为当时建议；实际冻结选择以 [protocol-v1.md](protocol-v1.md)、[protocol-cost-v3.md](protocol-cost-v3.md) 及各报告哈希为准，结果见 [结果页](../docs/results.md)。未被最终协议选择的网格和消融不能视为已经完成。相关反例见 [challenges.md](challenges.md)。

## 1. 三种效果必须分别回答

| 问题 | 固定什么 | 唯一主要变化 | 可支持的结论 |
| --- | --- | --- | --- |
| K：更新外部知识有没有用？ | 模型/adapter、提示、解码、问题、工具接口、执行策略 | 旧快照与新快照 | 外部知识刷新收益；不能称作模型学到了新知识 |
| B：SFT 是否改善同证据行为？ | 完全相同的原始观测字节、候选工具、上下文预算、评测状态 | 原始模型、QA SFT、更新行为 SFT | 条件动作/读证据能力；不能归因于检索提供了更多信息 |
| F：固定 adapter 能否处理未来变化？ | 训练截止点、adapter 哈希、推理设置 | 截止后未见事件、实体和组合；工具允许读取新证据 | 行为迁移与证据服从；不能称作持续参数学习 |

K、B、F 可以使用同一任务域，但不得只交一张端到端总分表。还要单独评测增量执行器的正确性与效率；模型错误和更新器错误不能混在一个无法诊断的数值里。

## 2. 先做强规则基线和独立真值

暂定域是软件版本、依赖和环境兼容性。其优点是版本/环境约束可以独立检查，不必再让生成模型裁判自己的答案。[PyPA 依赖规范](https://packaging.python.org/en/latest/specifications/dependency-specifiers/)明确包含版本限制、extras 和环境条件；项目先声明支持的规范子集。真实元数据的缺失不等于没有依赖，未知构建行为不能被默认为兼容。

先建立小规模有限世界：有限包版本、明确依赖、平台/Python/ABI 条件及明确优先级的合成政策。合成撤回、别名和例外均显式标注为实验覆盖层，不冒充真实发布事故。原始公共记录保留 URL、抓取时间、许可和内容哈希；历史元数据若没有可信快照，不得从今天的内容反推当时状态。

独立真值由从头枚举可行赋值/约束检查生成，不能读取增量执行器的 dirty 集合或缓存。再用独立证据检查器验证返回版本、全部必需约束和引用；两套实现不共享增量更新逻辑。共享规范解析库时必须披露共同失效风险，并保留手工推导的小反例、变异测试和交叉核对。

模型不能看到 gold、隐藏完整世界、未来事件或参考求解器的结论。规则策略作为可部署基线时也只经公开工具获取信息；全知参考仅负责评分。规则输出、模型原始输出和运行时拒绝/修复后的结果必须分栏，不能把兜底规则的正确答案计为模型成功。

**CPU 阶段先通过 C1–C5 的正确性检查，才值得花本机训练预算。** 如果不调用模型的强规则执行器已经满足全部目标，保留它作为主路线；只有真实语义理解或策略选择缺口才成为 SFT 目标。

## 3. 公平运行基线

| 标识 | 机制 | 不能故意削弱的能力 |
| --- | --- | --- |
| RAG-refresh | 普通增量索引，查询时重新检索并回答，不复用旧执行图 | 同样过滤快照/撤回、使用相同检索器与证据预算；不要求每个事件全量重建索引 |
| Agent-full | 每个被请求问题从头运行同一 Agent 策略 | 同样共享索引、工具缓存、批处理；不强迫扫描所有历史问题 |
| Positive-only | 仅传播已读事实/旧引用的变化 | 与主方法共用执行器；用于隔离缺少负依赖的后果，不是唯一竞争者 |
| Trace-predicate | 经典 trace runner：查询/目录集合节点、正负依赖、动态边替换和相等截断 | 与主方法相同可观察接口、相同缓存、相同快照合同；这是新颖性的必要强基线 |
| DeltaWeave | 主候选的证书、保守前沿、观测重验证、按需恢复/截断 | 必须明确多于 Trace-predicate 的具体机制；若没有，报告等价而不是包装成两个算法 |
| Rule-full / Rule-incremental | 强规则策略分别从头与增量求解 | 同样工具权限、公开信息与证据合同；不用 LLM 的耗时优势应如实保留 |

第一轮不必把 Graphiti/LightRAG/TG-RAG 的完整依赖栈全搬到 24 GB 电脑。它们的机制边界先做来源明确的比较；若要宣称优于某仓库，必须实际固定版本、匹配输入与预算运行。不能用本项目里的简化仿制版本替代原系统后仍沿用其名字。

必要消融为：去掉空/范围依赖、只 hash 最终值、相同值不替换边、去掉跨组件发布屏障、去掉按需调度/回退。消融只用于说明机制，不用于代替上述强竞争者。

## 4. 最小可裁决工作负载与数据隔离

首轮 CPU 机制套件建议从 8 个事件族各取 12 条独立事件链：C1 新例外、C2 来源替换与撤回、C3 原子快照混读、C4 政策/别名/工具域变化、C5 有效期与追溯更正、C6 大扇出、C7 低复用、C8 规则充分的任务。每条包含更新前、更新后和无关对照；按整个世界/事件链分组，不能把同一链的相邻状态拆进 train 与 test。

模型小样本诊断可先取每族 4 条 dev 链，用来判定长度、动作格式与本机成本。确认集建议至少每族 12 条独立新链，另有规模/复用率压力矩阵。小样本置信区间会宽；若无法排除实质退化，只能写“未能确定”，不能因为均值高就声称达标。

最终划分应同时满足：

- 实体/版本族隔离：train、dev、确认集的包和派生别名互不泄漏；同一反事实家族只在一侧。
- 时间隔离：训练截止点后事件不用于训练、提示修改或阈值选择；未来标签由已冻结的可执行规则产生。
- 组合隔离：单个基本约束可以在训练中出现，某些深度、例外与撤回组合只在确认集出现；另外报告熟悉组合与新组合，避免将外推和插值混为一谈。
- 反捷径：文档数量、引用数量、时间格式、来源名称、位置、ID、预算与标签不得单向绑定。成对改变事实，保留问题和非因果外观；成对改变外观，保留真值。
- 确认集冻结：数据字节、生成代码、协议、源码、基础模型、训练配置及 adapter 全部记 SHA256。看过确认集预测后再训练必须使用新的确认集，而不能继续把旧分数当最终验证。

固定注入调度用于 C3；预注册的事件/请求时间线用于成本实验。所有方法看到相同时间线，不得让主方法提前看到未来事件以提前维护。

## 5. K：外部知识更新效果

对每个冻结模型 M，分别运行 `(旧库, 全量策略)`、`(新库, 全量策略)`；提示中目标查询时间一致，旧库是明确的陈旧基线。再在新库上比较 full、positive-only、trace 和主方法，才是在测更新机制。

至少分成“答案改变”“答案相同但证据改变”“完全无关更新”三个分母。若只选答案改变的问题，会鼓励每次更新都猜不同；若只用无关更新，会夸大缓存收益。增加未更新旧记忆与新证据冲突的样本，检查模型是否真正服从新证据。

报告新知识后的严格正确率变化、需要改变却没有改变的比例、无需改变却被破坏的比例、引用更新正确率及完整链全通过率。即使新库带来大幅提升，模型参数没有变化时也只能写“检索/执行更新有效”。[MQuAKE](https://aclanthology.org/2023.emnlp-main.971/)说明直接事实更新与其多跳后果应分开检查；本项目借鉴这一诊断，而不是复现其编辑算法。

## 6. B：同证据 SFT 行为增益

必要模型条件为 `M0` 原始官方蒸馏模型、`Mqa` 证据条件 QA SFT、`Mbeh` 更新行为 SFT。`Mqa` 应是强 open-book 基线：相同训练世界和证据，训练最终结构化答案及引用，而非刻意用闭卷记事实的弱基线。`Mbeh` 在相同世界上学习何时重查、发现例外后补哪类信息、何时不可确认及如何回答。监督只覆盖可审核的动作和答案，不把检索输入当目标，也不要求保存或评分自由长链思维。

训练条件尽量匹配可训练参数、优化器、超参搜索次数与监督 token 总量；同时公开独立世界数、目标 token、输入 token、step、epoch、峰值内存和墙钟时间。只匹配 step 会因轨迹长度不同而不公平。若同时无法匹配独立样本数与 token 数，先给一个明确主比较，再做小规模敏感性说明，不能隐瞒差异。

执行两层测量：

1. **固定状态测量**：同一观测字节与可用工具送给三个模型，评下一步动作、是否需要补信息、最终证据引用。一个动作可能有多个有效替代方案，判定合法进展/成本而非只接受参考轨迹的一个序列。此层隔离证据服从和动作选择能力。
2. **闭环测量**：同一初始状态、工具与预算，自由执行各模型策略，允许它们获得不同后续证据；单独评全任务成功与成本。此层收益包含策略造成的检索变化，不能再称作“最终上下文完全相同”。

用 gold 充分证据回答诊断阅读失败，用参考合法动作序列诊断策略失败，用完整规则证据诊断检索失败；这些是离线定位工具，不是计入主分数的隐形 oracle。原始输出先评分，格式修复/规则阻断另列。固定温度与种子不能保证不同硬件上逐字确定；需要记录运行栈，并用任务级判分而非把所有字面差异算错。

[RAFT](https://arxiv.org/html/2403.10131v2)是证据条件微调及干扰文档训练的近邻，但其部分无 gold 文档的训练样例仍要求答案，意在帮助记忆。本项目处理证据不足时不应照搬这一目标；否则可能训练模型在撤回后继续给出旧事实。

## 7. F：固定 adapter 的未来变化，以及另列的遗忘问题

选定 `Mqa`/`Mbeh` 后冻结 adapter，后续只改变库。测试其面对训练后新增版本、撤回、例外组合和新实体时是否正确行动。核心是单因素反事实：问题不变，足够的新证据改变时答案必须随之改变；足够证据全部撤回时必须承认不足；仅无关元数据变化时不应凭空改结论。

对照 `M0` 同样读取未来证据。若固定 `Mbeh` 与 `M0` 无差异，就不能声称更新行为训练必需。若只在见过的模板上改善，限定为模板内迁移；如果需要每次事实更新都重新训练，便否定“固定 adapter 适应未来变动”的强主张。

**冻结模型不存在由这段时间内参数更新造成的遗忘**，但仍可能被旧知识先验压过证据。真正的 SFT 遗忘要作为另外的可选阶段：按三个更新批次顺序训练，对比无重训、QA 更新、行为更新及带固定大小 replay 的行为更新；每批回测固定旧任务和少量一般格式/工具任务。成本不足可以不跑，此时不能写“已经解决灾难性遗忘”。[TRACE](https://arxiv.org/abs/2310.06762)的任务与模型不同，只支持将旧能力保持作为单独测量维度，不支持预言本项目的具体退化数值。

## 8. 指标与分母

| 指标 | 精确定义/分母 |
| --- | --- |
| 严格任务成功 | 正确结论 + 合法且充分的证据/引用 + 快照一致 + 满足动作合同；分母为全部请求，超时/无输出均不成功 |
| 可答成功率 | 严格成功的可答请求 / gold 可答请求；不能被大量拒答掩盖 |
| 不应回答却回答 | gold 不可答且实际输出 answer / gold 不可答请求 |
| 证据合同未通过的回答比例 | 错值、缺/错引、失效证据、混读或本不应答的 answer / 全部可解析 answer；无 answer 时为不可估计，而不是 0 风险 |
| 覆盖/格式 | 可解析 answer / 全部请求；合法结构 / 全部原始输出；与上一行同时报告 |
| 新依赖取得率 | 完成所需新增依赖的请求 / 确实需要新依赖的请求；核对工具日志，猜中不算取得 |
| 错误复用率 | 复用后违反当前快照合同的请求 / 发生复用的请求；同时给全部请求分母与计数 |
| 整链全通过 | 所有时间点及引用均严格正确的链 / 全部独立链 |
| 触发与重验证 | 被匹配 watcher、重查询节点、真实观测改变节点、最终模型调用分别计数；避免把重验证称为全是必要重算 |
| 总成本 | 首次构建、全部更新维护、查询、失败、重试和 fallback 的累计墙钟、CPU/内存、工具次数、扫描行数及模型输入/输出 token |

不要把 full-agent 的答案当 gold；它也会推理错误。对执行器可要求“与同一确定策略从头执行的结构化轨迹/结果一致”，对任务质量仍用独立规则真值。这样能分别定位执行器和模型的错误。

## 9. 公平预算与执行顺序

建议模型 dev 上预先只比较两档公开预算：每请求最多 4 或 8 次工具调用，总输入 4,096 或 8,192 token，总生成 512 或 1,024 token（跨所有轮次累计）；实际上下文上限和 24 GB 内存需由 tokenizer/本机预检确认，未测前不承诺适合。若预算不足，扩大所有方法同档预算或报告失败；不得只为主方法追加重试。是否计思考 token、停止符和输出解析必须统一。

更新验证的纯 CPU 数据库读单独累计，不能混进未收费的“免费工具”。规则策略的逻辑工具请求同样记录；它无需人为消耗模型 token。全量与增量策略使用同一模型权重、adapter、tokenizer、量化和解码，预算上限是相同的，不要求它们必须花完相同费用。

效率报告分两层：`stream-total` 从初次准备到最后请求的所有成本；`warm-query` 在已支付维护后的一次查询。另列模型加载的冷启动成本。CPU 重复运行可取 5 次并公开原始值，模型真实计时至少在同一小子集重复；报告中位数与范围，不以混合 batch 吞吐冒充单请求延迟。

为了节约本机推理，可缓存完全相同模型输入的原始输出做执行器对照，但必须显式记录 `replayed`、逻辑调用/token 与真实物理执行时间。不能把 replay 获得的耗时当作各方法独立实际推理耗时。不同输入不能偷用 gold 或其他方法结果；另设固定子集做真正端到端计时。

阶段顺序建议：CPU 微反例与强规则 → 原始模型诊断 → 决定是否需要 SFT → 等预算 QA/行为 SFT → 仅 dev 选型 → 冻结 → 新确认集 → 成本压力及失败归因。相同确认集上的多次训练迭代属于开发，不再是独立验证。

## 10. 预先写下可推翻结论的条件

- 任一受支持的确定性微反例产生静默错误复用或混读，执行器正确性主张失败；不能用更好的模型总分抵消。
- DeltaWeave 与 Trace-predicate 没有机制和结果上的实质区别，接受经典方法应用的定位。
- 只减少模型次数却增加包含维护的总成本，只能报告推理调用节省；不同负载的盈亏区间必须保留。
- `Mbeh` 在固定状态下不优于强 `Mqa`，不能声称更新行为监督必需；若 `M0` 已足够，则优先减少训练。
- 未来证据更新后仍服从旧事实，固定 adapter 的未来迁移主张失败；不能通过测试后重训修饰为原协议成功。
- 非劣性/优势用按独立世界或事件链配对的置信区间，不按相邻状态当独立样本。建议质量容忍差值在冻结前定为最多 1 个百分点；若样本量不足以判别，就报告证据不足。正确性微反例则零容忍，不用均值稀释。

本阶段应交付的是能重放事件、分离数据与模型收益、公开失败和总成本的研究证据。是否达到业务级可靠性、是否值得使用 SFT、是否优于经典增量维护，均由上述实验决定。

# 引用接口独立确认协议 v1

本协议在六步开发演示之后制定。开发结果不得改写：完整复制与保留完整上下文的引用视图各完成 1/6 会话，紧凑引用视图完成 4/6；缓存失败和新鲜生成分开计数。后续不依据确认结果修改提示、训练权重或此处输入。

目标是检验冻结 adapter 对三种**接口传输形式**的适应性，并验证宿主展开不会接受旧、损坏或跨请求引用。单个合法引用的闭合接口不测模型独立依赖求解、事实核验或多证据推理。规则控制器是完整可用的强基线，模型为可选组件。

## 输入与冻结

生成种子固定为 `20261031`。使用 8 个已知机制族，各 2 条新合成链，每条 3 状态，共 16 链、每视图 48 个会话：新增策略引入环境读取、候选撤回/插入、同值更换来源后撤回、原子跨行变化、别名进入被限制项目、仅时间改变、未知环境字段、有限候选池扩充后删除完整性证书。这些是未运行过的新实例和组合，不声称新机制或真实 PyPI 事故。

每族短副本不预验证旧观察，长副本预验证；后者增加 6 个真实传递依赖、每个 2 个版本，达到至少 5 包和 25 引文的完整结果。替换根元数据时保留这些依赖，避免长证据只作为无意义填充。覆盖 wait、ask、refresh、answer、abstain、冲突与不完整目录。oracle 从独立字典重放事件，不读取生产 Store 来生成真值；可行 selection 通过独立 witness 检查，不要求多解时碰巧选中同一组版本。解析器仍共享 packaging，存在共同实现风险。

`prepare` 先以拒覆盖方式保存 cases/config/源码 SHA-256 manifest，然后运行三视图 rule + oracle 审计并封存 audit seal。只有审计通过且全部冻结文件/源码摘要一致才允许模型确认。所有记录来自实际执行；失败也保存。禁止输出后删失败样本或改分母。

## 三个视图与预算

- `full`：原完整输入与完整 JSON 复制合同，保持既有提示。
- `reference_context`：仍给完整事实观察，但输出当前短引用；隔离输出复制因素。
- `reference`：只给动作所需状态与短引用，完整数据保存在宿主；同时改变输入负担，单独解释。

引用提示固定 `bound-observation-reference-v2`。第 5 条明确 resolved/conflict 均复制当前引用，不再与旧的 conflict 空 selection 规则冲突；其余 publication/ask/refresh/abstain 优先级保留。

三视图使用相同 48 个状态、coarse 引擎、每会话最多 3 个动作、同一链内语义缓存和每链新 Session。错误输出也可缓存；不重试抽样、修 JSON 或替换答案。模型设置与现有本地 CLI 一致：seed 42、bf16/MPS、temperature 0.6、top-p 0.95、top-k 0、最多 2048 输入和 2048 新 token、每次最多 120 秒。具体设置及按提示派生的种子规则写入 config。不得静默截断超长输入；超过预算仍是接口失败，不能删除。

固定模型/adapter 摘要写入 run-binding，所有模型输入只含公开 state，不含独立 oracle 标签。若比较 SFT 增益，base、QA adapter 与行为 adapter 必须使用同一协议、视图、数据和预算。若只运行一个冻结 adapter，只报告该接口上的表现，不称为 SFT 因果增益。

## 验收与分母

1. **新鲜原始合同正确率**：严格动作与公开接口合同匹配且生成完成 / 新鲜生成次数。包含 refresh 等中间动作；缓存命中不充作新生成；rule 分母为 0，比例为 null。
2. **所有会话完成率**：状态 completed / 48；另报全部会话的 oracle 合适终止比例。wait、ask、abstain 可以是正确终止，不是完整回答。
3. **错误引用接受率**：已实际展开但未通过独立 query/snapshot/runtime/完整内容/收据/原始引用核验的次数 / 实际展开的引用数。没有展开时为 null。raw 动作比较通过但展开前被 guard 阻断，不算错误交付。
4. **完整回答 oracle 符合率**：实际发出的 answer 满足当前有限世界状态、witness 和引用存在性 / 实际发出的 answer 数；没有回答时为 null。宿主展开内容不得算模型逐字生成。
5. **成本**：仅累计新鲜生成的实际 input/new tokens 和生成秒数，缓存命中另列；缺失收据记 unknown，不填 0。模型加载时间另存。不同视图的输入/输出长度变化本就是接口干预，不声称只靠依赖算法获得这些收益。

规则审计要求三视图 48/48 正确终止且展开后的完整答案逐一一致。模型没有用规则结果替代失败的通关机制，不预设或虚构达到某个质量门槛。任何错误引用被展开都必须独立报告并阻止正面安全结论；没有观察到错误也只是这组有限测试的结果。

现有 CPU 回归另外覆盖旧引用、同值新绑定、碰撞、跨快照/代码版本、不可变记录和推理中并发提交。当前请求固定开始时快照；之后的提交不允许改变该请求已绑定的对象。内容摘要只证明字节一致，不能自证事实真实性。

## 命令

```bash
python scripts/benchmark_reference.py prepare --output experiments/reference-v1
python scripts/benchmark_reference.py run --bundle experiments/reference-v1 \
  --view reference --model .cache/deepseek-r1-distill-qwen-1.5b \
  --adapter runs/behavior/adapter --output runs/reference-behavior-confirmation
```

模型执行是显式独立步骤。`prepare` 不加载模型，不使用 GPU；各输出路径必须为新目录。每个会话及时保存原始动作、宿主 proof 记录、展开答案和核验结果，最终再保存汇总，失败也保留。公开底层完整数据不等于模型独立推理出了这些数据。

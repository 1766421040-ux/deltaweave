# 预先确定的首轮协议 v1

记录时间：2026-10-28。本文件在首次正式模型 dev/训练/保留集运行之前写入；可行性预检已完成，预检的两个手工例子不属于正式数据。发现实现缺陷可以修复，但必须保留失败记录；看过保留集预测后改变提示或训练，必须另建确认集。

## 主问题与先后顺序

首先验证确定工具执行与从头重跑是否一致，及总成本在哪些条件下有收益。之后测模型是否遵守已经验证的证据。系统正确性不由模型自己评分，也不由 full-agent 输出充当真值。

1. CPU 反例及有限状态回放：插入/删除/空查询、动态换支、同值换依赖、原子多行更新、固定快照、显式政策/环境/时间/代码版本。
2. CPU 成本：full（同快照共享 memo）、positive（刻意缺少集合依赖）、coarse（项目范围+经典截断）、predicate（完整等值过滤范围+相同截断）。所有模式共用查询与索引实现。记录首建+事务应用+查询+证书检查+图维护的总时间，另外给各项计数，不以计数代替时间。
3. 真实文件元数据：37 条公开 PyPI universal-wheel 记录。生产 resolver 与独立有限赋值 oracle 核对；不推断运行时兼容，也不把有限域无解当全 PyPI 无解。
4. 本地 DeepSeek 状态控制实验。然后才运行冻结模型的知识更新闭环，明确记录真实模型调用与普通内容缓存。

## 模型与训练

- 官方 `deepseek-ai/DeepSeek-R1-Distill-Qwen-1.5B`，revision `ad9f0ae0864d7fbcd1cd905e3c6c5b069cc8b562`；BF16/MPS，仅当前 Mac。下载文件 SHA 已校验。
- 原始模型 M0；证据条件 QA SFT 的 Mqa；更新行为 SFT 的 Mbeh。统一用户 prompt、官方 thinking prefix 与结构化动作合同。
- rank 4 / alpha 8 / dropout .05，对 q/k/v/o/gate/up/down 投影；FP32 adapter、AdamW lr 2e-4、梯度裁剪 1.0，batch 1、梯度累积 4。按 completion token 归一窗口损失。
- 训练 seed 42；单一配置，不做保留集调参。每条最长 1024 token，超长拒绝，绝不静默截断。只监督 completion 和一个 EOS。
- 主预算为至少 16,384 个监督 token，在完整 optimizer window 后停止；公开实际超额、step、样本次数、输入 token、世界覆盖、loss 和墙钟。允许 dev 证明明显未收敛后追加至 32,768，但两条训练路线同时追加、保留初始结果，并在打开保留集前决定。
- Mqa 使用同一 96 个训练世界里的充分证据/冲突/缺元数据/缺 Python 状态；Mbeh 另有证据过期、未检索、发布未就绪和认证复用。Mqa 是 terminal open-book QA 基线，不是闭卷背事实。不同状态覆盖正是干预；token 相近不代表独立信息完全相同。

## 模型数据与分母

`data/learning/manifest.json` 固定文件哈希。训练 96 世界，Mbeh 768 条、Mqa 384 条；dev 4 世界×8状态；test 4 世界×8；future 4 世界×8。整个世界不跨 split。future 是合成的未见条件组合与实体，不是尚未发生的真实 PyPI 时间序列。

这是**闭合接口的状态控制实验**：resolver 状态和证据合同是合法工具输入，模型选择 wait / ask / refresh / answer / abstain。强规则控制器可以精确执行此合同。因此不能用这里的高分声称通用自然语言理解、独立依赖求解或 SFT 必要性。终端输出包含版本和引用，必须完整复制正确，不能只评 action。

同一 prompt 与解码 seed 分别给 M0/Mqa/Mbeh。主生成预算每条 2048 新 token / 120 秒（包括 thinking）；temperature .6、top_p .95，明确 EOS/截断/超时。严格格式、动作、完整 payload、可答成功和不应回答却回答分别报告；失败不从分母消失。任何宽松解析仅作辅助且不能补写事实。

test/future 各只有 4 个独立世界，区间会宽。按世界整链成功与逐状态成功同时给出，不能把相关的 32 条当作 32 个完全独立任务。需要更多统计把握时扩展独立世界，不能只增加同一世界的改写。

## 闭环与缓存公平性

更新后实际重新取得工具观测，过期时采取 refresh；新快照足够时回答，不足时停止。原始模型输出与规则拦截/修复分开，禁止用规则目标覆盖模型预测再记为模型成功。

完整求解与增量求解都可使用跨快照的完整语义提示缓存；需要记录模型/adapter、prompt、解码与 seed。若相同工具结果使普通内容缓存也省掉同样的模型调用，结论就是两者相同，不能人为禁止 baseline 复用。

## 改进和停止判断

- 任一正确性反例失败：先修执行器，不训练掩盖。
- 细粒度比 scoped coarse 更慢：保留 coarse 作为推荐，不宣称更细更优。
- 规则已满足结构化任务：规则作为主路径，SFT 仅报告可选行为适配的真实收益和成本。
- 模型 dev 未达到合同：诊断格式/状态判别/载荷错误；在确认集前修复或调整统一预算，所有改动进入研究日志。
- 不设置“必须超过某仓库”的结果目标。不复现的仓库仅作方法参考。

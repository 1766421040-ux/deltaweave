# DeltaWeave：更新语义、正确性条件与可反驳主张

状态：2026-10-28 最初写成的研究设计与推导。其后已完成有限状态、独立领域 oracle、更新成本及本地模型实验，实际结果见 [results.md](../docs/results.md)。下文保留设计时的条件和待验证路线，不把全部建议当作已实现功能。本文的“命题”是条件化论证，不是已机械验证的定理，也不是模型质量结果。领域采用有限 PyPI 发行文件集合；所有模型运行均在用户授权的本机完成。

## 1. 决策：先研究什么

暂定主线是 **在受控工具接口上显式记录观测依赖，使数据库更新后的 Agent 执行与同一快照上的完整重跑一致，并测量为这种保证付出的全部维护成本**。

“动态图 + 结果不变时停止传播”不是新算法：构建系统的 verifying traces / early cutoff、Adapton 的动态依赖修复、Salsa 的 backdating 已提供直接先例，见 [prior-work.md](prior-work.md)。本项目候选贡献限于：

1. 给 Agent/RAG 工具的集合查询、空查询、排序候选与适用条件建立可审计的依赖边界。
2. 将模型执行、证据与生成的训练样例放进同一版本语义，明确哪些结论能继承、哪些必须重新验证。
3. 用刻意构造的新候选、读集换支、过期与部分发布事件检验正确性，并报告证书维护后的净成本。

当前不能声称：一般自然语言问题的最小依赖集、任意知识图的精确失效、任意模型的语义等价、自动遗忘旧参数知识，或必然比全量重算更快。

## 2. 状态、观测与两种“正确”

一个发布快照记为

\[
S_r=(D_r,I_r,P_r,E_r,C_r,\theta_r),
\]

其中分别为有限数据集、已提交检索索引、组织策略、显式运行环境、工具/提示/序列化/求解器配置、模型参数。快照包含这些对象的不可变标识；某对象没有变化，可以继续引用同一对象。原始远端抓取时间和本地发布版本分别记录，不能把跨项目抓取冒充 PyPI 的全局原子快照。

一次只读 Agent 执行是一个终止的有序调用轨迹。将调用展开为节点形成执行 DAG：源查询节点读取快照；推理/求解节点读取前驱的公开输出；控制节点根据前驱结果决定后续调用。这里的执行 DAG 不等于包依赖图；后者即使出现回路，也不能靠“DAG”假设解决求解问题。重复调用可在同快照内按稳定键共享，但循环须有明确终止或预算耗尽语义。

对于调用描述符 \(\kappa\)，工具产生公开观测

\[
o_{\kappa,r}=\operatorname{Canon}(\pi_\kappa(Q_\kappa(S_r))),
\]

\(\pi\) 是工具实际交给调用者的投影，\(\operatorname{Canon}\) 是固定序列化。模型只能读取该投影，不能另取未追踪原始记录。规范化不允许删除模型实际可见的区别：若原始顺序会进入提示，就不能先排序后宣称输入等价；引用 ID、缺失标记、截断标记、错误状态、适用环境同样可能是有效信息。

需要分别评价：

- **更新一致性**：复用/局部重算的输出，与同一 \(S_r\)、同一配置的完整重跑输出相同。完整重跑也可能答错。
- **任务正确性**：输出符合独立的元数据/约束求解真值。更新一致性本身不证明这一点。

同样区分“观测相同”与“答案碰巧相同”：前者可在满足确定性前提时支持复用；后者不证明读集或未来依赖未改变。

### 快照 envelope 与语义输入分离

不能把全局 `snapshot_id` 当作每个 LM prompt 的 nonce：即使只有不相关项目变化，这个字节也会使所有模型输入不同，消灭跨快照复用。建议分成两个对象：

- **Host envelope**：本次请求固定的 manifest、有效性检查版本、请求/事件编号、缓存命中事实及索引就绪状态。由执行器检查和记录，不自动写入模型提示。
- **语义输入**：模型真正接收的用户参数、显式环境、稳定来源 ID/内容 revision、工具观测字节及必要策略内容；同时固定模型、解码器、提示与代码版本。

模型节点的计算键可概念化为

\[
K_v=H(\text{node-code},\text{model},\text{decoder},\text{prompt},
\text{semantic-args},\text{ordered-observation-bytes}).
\]

不把无关的全局发布号放进 \(K_v\)。这不允许删除真正有语义的 `as_of`、用户要求的历史版本、策略条款或工具版本：只要执行逻辑/模型实际读取，就必须参与身份或依赖校验。一次全局策略变化可以先使相关工具查询重新验证；若模型可见的投影最后确实相同，模型节点仍可能复用。

被证明未受影响的证书可以把 `validated_at` 推进到新快照，但保留 `computed_at`、原始 trace 与原始来源 provenance；记录本次采用了哪项不变性检查。引用应锚定不可变文件/记录 revision，再由 host 给出本次有效的 manifest，不能伪造重新检索/重新生成的时间。

本文的重跑等价比较 **语义结果、引用合同与当前快照上的有效性**。缓存命中标记、实际生成时间和历史执行收据按真实发生情况记录，本来就不要求与“刚刚完整重跑”的审计字节相同。

## 3. 证书究竟证明什么

一份查询证书至少包含下列逻辑内容；字段实现可以更紧凑。

| 内容 | 用途 |
|---|---|
| 操作、规范化参数、环境、组织/租户范围、策略与工具实现版本 | 定义当前究竟执行了哪个查询 |
| 查询域及完整性状态 | 指定结果相对于哪个有限全集完整；区分完整、截断、采集失败与未知 |
| 已返回记录的不可变内容标识、公开观测字节或摘要 | 校验正读依赖及公开结果是否变化 |
| 可保守触发的订阅范围/谓词 | 捕获新插入、移入范围、移出范围、删除、规则改变和空集合变非空 |
| 必要的排序、聚合、索引或候选集合版本依赖 | 捕获没有旧正引用边的新候选与全局排序变化 |
| 创建版本、最近验证版本、实际调用轨迹 | 不把“在新快照验证过旧结果”写成“模型在新快照重新运行过” |

这里的“证书”是由可信工具适配层生成、可重放检查的记录，不是 LLM 自述，也不是无需信任数据源的密码学证明。只存 `hash(result)` 并不能证明完整性；还需要结果发生变化时必定被触发的机制。

对证书 \(c\) 及完整事件批次 \(\Delta:S_r\to S_{r+1}\)，定义保守触发器 \(W(c,\Delta)\)。最低充分条件为：

\[
o_{\kappa,r+1}\ne o_{\kappa,r}\implies W(c,\Delta)=1.
\tag{COVER}
\]

允许误触发；不允许漏触发。只有 `W=0` 且 COVER 已由接口实现保证时，才能免查询地复用。`W=1` 只是“可能变化”，仍需重算/校验公开观测。没有可证明的精细触发器时，订阅整张关系或整个本地数据分片是正确但较贵的回退。

COVER 比较的是固定逻辑查询描述符。参数或明确绑定的策略版本变化时，这是新的调用身份，不能拿旧描述符的证书冒充新调用。若用户请求“当前组织策略”，解析当前策略版本这一步也必须是受追踪读取；不能在同一不可变键下偷偷把旧策略解释成新策略。schema、alias 解析和默认环境选择同理。

### 三类读依赖

- **点读**：读取 `artifact_id` 的某些字段；删除和字段改变均触发。不存在该 ID 的点读也需要一个可触发的缺失键订阅。
- **集合/空集读**：`eligible(project, environment, constraints, policy)`；已返回项只是支持集合，项目候选域和适用谓词才覆盖未来新增项。空结果仍保留完整订阅。
- **范围、聚合和 top-k 读**：候选域、评分/排序规则、稳定打破平局规则都属于查询定义。BM25 语料统计、嵌入模型或近似索引构建方式变化，可能改变已有记录的排名，不能仅订阅返回的 k 个 ID。

更新事件匹配必须考虑 old/new 两侧；只看新值会漏掉移出范围和删除。对连接查询，只检查一行的局部条件通常不足以保证 COVER：另一关系新增匹配行也可改变结果。首版可用关系/项目级订阅保守覆盖，再测更精细索引是否值得。

PyPI 的“完整”仅指本地冻结候选域及显式发行文件。若候选池、发行文件元数据或某环境依赖未收齐，工具返回 `incomplete/unknown`，不能产出全 PyPI 的“不存在可行版本”结论。`packaging` 处理单条 requirement、版本与 marker；联合可行性另由独立求解器核验。

## 4. 四条可比较的更新路线

下列 U1—U4 是本文件内部的更新执行路线，不覆盖 `research-state.yaml` 中独立的参数更新研究分支。

| 路线 | 数据更新后的行为 | 能成立的条件/主要反例 |
|---|---|---|
| U1 完整重算 | 在新快照重新执行所有被请求的根；同快照共享相同子调用，避免故意削弱基线 | 基准参照；仍依赖数据/工具正确与生成可复现，不自动等于真值 |
| U2 仅正行依赖 | 仅由旧轨迹返回的记录 ID 找受影响根，保守重跑这些根 | 新版本插入、空集变非空可漏失效。这里特指“返回行 ID”粒度；完整集合本身作为正输入的经典依赖跟踪不受此反例否定 |
| U3 谓词/域失效 | 在 U2 上加入 COVER 订阅；匹配后重跑旧图中全部相关且被请求的下游，执行中发现新边 | 条件化正确；若广泛域变化但公开观测不变，会做多余推理 |
| U4 观测等价停止 | 使用与 U3 相同的证书与触发器；校验/重算节点后，只有公开输出变化才让其消费者重算，动态更新读集 | 在下节条件下与 U1 一致；属于经典 early cutoff 的应用，成本未必更低 |

U3 与 U4 必须使用同一来源、公开工具合同、证书范围及事件；否则无法把差异归因于停止传播。U2 是暴露缺失集合依赖的有意受限基线，不能作为唯一有竞争力的基线。

## 5. U4 的执行规则与条件化论证

### 执行规则

1. 固定待发布的 \(S_{r+1}\)，在私有工作版本中消费完整事件批次；查询/索引未就绪则不把它标成可发布。
2. 对实际被请求的根检查旧轨迹。工具证书由 COVER 触发器判断；推理节点还检查模型、提示、环境、代码及调用参数版本。
3. 按旧执行中的依赖读取顺序验证。遇到第一次改变，重跑当前节点，不盲目执行旧轨迹中之后可能已失效的分支。新调用先获得该快照上的有效结果，再交给调用者。
4. 查询重算后比较其公开观测；推理节点重算后比较其公开输出。如果不变，可以停止向消费者传播；如果改变，继续修复消费者。
5. **不论输出是否改变，执行过的节点都必须替换为新读集、新订阅和新证书。** 不复用已经消失的动态边，也不遗漏新边。节点输出、轨迹及订阅的发布须一致。
6. 根及其所需闭包全部有效后，原子发布 manifest 指针。失败保留旧发布快照或返回不可用状态；不能发布一半。后台已有其他未请求根仍可保持惰性，但它们没有新版本有效性声明。

### 命题 A：有限、确定执行下的重跑等价

若下列条件同时成立，U4 对每个完成验证的根产生与 U1 在 \(S_{r+1}\) 上相同的公开结果。

- **A1 一致快照**：整条执行只读一个不可变快照；所有数据库、索引、策略与工具响应都属于该快照。
- **A2 完整可见输入**：每次外部读取经过被追踪工具；模型/提示/配置/时间/环境，以及影响查询解释的 schema、名称规范化/alias namespace 也作为输入。工具不隐藏影响输出的状态。
- **A3 保守覆盖**：所有查询证书满足 COVER；没有遗漏事件，或使用整域版本改变回退补偿未知缺口。
- **A4 观测等价可判定**：比较完整公开值。理论使用字节等值；只用哈希的实现额外依赖无碰撞假设，测试可用原字节比对消除该假设。
- **A5 执行语义固定**：节点是显式输入的确定函数，执行终止；求解器和工具的平局规则也固定。动态分支按读取顺序处理，新边和替换后的旧边都正确维护。
- **A6 生命周期正确**：证书与输出一起提交；复用前验证；不能因缓存命中忽略代码或模型版本改变。

证明思路：沿完整重跑的实际轨迹作归纳。源查询若未触发，则由 COVER 的逆否命题得到公开观测不变；触发时直接在新快照重算。对内部节点，所有已读公开输入及配置相同，则由 A5 输出与后续调用相同；首次不同的输入导致节点重跑，随后发现的新依赖也从新快照读取，旧的后续分支不再被当成必需。重算输出相同时，消费者所见输入相同，因此可以停止；即使读集已变，A6 保证下一次更新有正确触发路径。有限终止给出根结果与完整重跑相同。

这是一项框架适配的条件证明，不是新的通用增量计算定理；类似论证见经典工作。它也不证明“只重算了逻辑上必要的最少节点”，因为触发器可能保守，比较之前也可能必须付出重算成本。

### 命题 B：正行读集无法一般覆盖插入

旧数据库为空，工具查询“是否存在满足范围的发行文件”，返回 `false`；旧正行读集为空。新数据库插入唯一满足条件的发行文件，真结果为 `true`。任何仅由旧返回行 ID 命中触发、且不追踪查询域的策略都不会触发。这一反例只需一个查询和一次插入，无需多跳图或语言模型。

### 命题 C：输出不变不能省略读集替换

令 `choose(flag)=read(A)` 当 flag=0，否则 `read(B)`，初始 A=B=7。第一批更新仅把 flag 从 0 变 1，节点输出仍为 7。若因输出不变而保留旧 A 边，第二批把 B 改成 8 时将漏失效。停止传播允许省去消费者重算，**不允许省去当前节点的新依赖记录**。

## 6. 保证的边界与最短反例

| 缺失条件/错误捷径 | 最短反例 | 应有处理 |
|---|---|---|
| 只看候选数量 | `{1.0}` 替换成 `{2.0}`，数量仍为 1，但“最新”改变 | 比较实际公开投影，不比较计数代替内容 |
| 只看新行匹配 | 唯一满足策略的记录被删除或移出范围 | old/new 匹配；缺 before image 时采用更宽域失效 |
| 把空集理解成无依赖 | 初始无允许版本，插入一个允许版本 | 空查询保留域/谓词订阅 |
| 只关注原版本字段 | 增加组织例外或改 Python 环境，原版本未改但适用性改变 | 策略、环境、求解器版本均为显式输入 |
| 仅版本号相同就停 | 相同版本的公开引用集从 `{file-A}` 换为 `{file-B}` | 若引用是输出合同的一部分，输出已改变；需更新消费者或把渲染拆成独立节点 |
| 同 digest 代表任何问题都相同 | 工具投影省略 yank 状态，但模型另从原始行读 yank | 禁止旁路；否则扩大投影和依赖合同 |
| 输出相同保留旧轨迹 | 命题 C 的 flag/A/B 两次更新 | 原子替换轨迹和订阅，仍可停止向下游传播 |
| 重查旧分支不按顺序 | flag 改变后旧分支的文件已不存在；先执行旧分支产生错误 | 在决定分支的前驱改变处重新执行当前节点 |
| 数据库新、索引旧 | 新数据库已撤销许可，旧索引仍返回允许记录 | 快照绑定 + 就绪发布，不能用当前数据库版本给旧索引背书 |
| 一条回答混用快照 | 同事务把允许版本从 1 改 2，两个工具分别读到新/旧状态 | 每个根固定一个 manifest；“时间接近”不构成一致性 |
| 忽略时钟 | 无数据库写入，但有效期已到 | `as_of` 作为显式输入；有效期边界产生更新事件或强制重验证 |
| 忽略模型更新 | 数据不变但 LoRA 已替换，旧回答仍命中 | 模型 revision 作为计算身份；共享冻结观测，不默认共享模型输出 |
| 近似检索假装完整 | 新高分候选没进 ANN 返回集，旧 top-k digest 未变 | 只能保证相对该工具返回值的重跑一致，不能保证真实 top-k；精确检索作为有限实验真值 |

### 三项不能凭系统记录获得的保证

1. **未观测世界的完整性**：若两个真实世界给系统同一份已采集数据，而其中一个世界存在未采集的可行版本，两者在系统内不可区分。没有来源完整性假设，就不可能保证全世界范围的否定答案。
2. **学习出的依赖范围没有漏项**：LLM 预测谓词可以用作调度提示，不能独自承担 COVER。允许其建议更小的域，但必须由工具合同检查，失败即采用保守域。否则只可报告经验漏失效率。
3. **随机模型逐次完全一致**：固定 seed/greedy 并不自动证明某硬件实现逐位确定。若同输入重复执行仍不同，严格重跑等价仅适用于确定的工具/状态层；模型层应单独给重复运行与任务正确性结果，不把分布上的近似一致写成严格等价。

## 7. 证书成本必须进总账

设一次批次 \(\Delta\) 后请求根集合为 \(R\)。对路线 \(j\)，记：

- \(A(\Delta)\)：共同的数据采集、应用事件、基础索引更新成本；同时报告而不藏入实验外。
- \(M_j\)：证书订阅索引维护、事件匹配、失效标记、缓存查找与图遍历。
- \(Q_j\)：实际执行/验证的查询节点集合；每个节点成本含查询、投影、序列化/摘要、完整性检查和证书写回。
- \(N_j\)：实际执行的非查询节点集合；包括模型生成、约束求解及新旧动态边维护。
- \(P_j\)：验证结果与 manifest 提交、必要持久化及回收成本。

则报告的批次更新时间应是

\[
T_j=A(\Delta)+M_j+
\sum_{q\in Q_j}(t_q+t_{canon,q}+t_{cert,q})+
\sum_{v\in N_j}(t_v+t_{edges,v})+P_j.
\]

冷启动的初始证书构造 \(B_j\)、空间峰值 \(S_j\) 与内存回收另报；累计 n 批的成本为 \(B_j+\sum_{i=1}^n T_{j,i}\)。U1 不应被强制支付增量路线专用的订阅维护；它仍享有同批共享子调用和正常模型缓存配置的公平条件。

没有索引的事件×订阅匹配可达 \(O(|\Delta|\cdot |C|)\)；重建完整集合摘要需要读其规范化内容，不能写成“哈希比较 O(1)”就略过生成哈希的成本。若使用分片版本、Merkle 结构或物化查询避免扫描，应计入其初始化、更新和存储成本，且明确该结构如何保证 COVER。本文不假定这些优化已实现。

U4 比 U3 更快的必要经验条件是：省掉的下游工作大于额外比较及细粒度维护工作。若图很小、所有观测每次都变、查询验证比推理还贵，U4 可能更慢。若语义不变但原始文本总变化，字节等价的保守停止也可能几乎没有收益；不得改用未经证明的“语义相似”偷偷提高命中率。

分别报告更新处理时间、发布延迟、查询响应时间及模型 token/调用数，避免把后台工作挪走就声称总成本下降。惰性维护与急切维护只在相同最终请求集合及更新时间窗下比较。

### 选择校验/重算前沿，而不是默认越细越好

把能够满足 A1—A6 的执行计划集合记为 \(\Pi_{safe}\)。计划可混合三种安全动作：用未变的完整域版本确认有效；执行精确查询/比较；直接在新快照完整重算一段子执行或整个根。研究目标可写成

\[
\min_{\pi\in\Pi_{safe}} T(\pi;\Delta,R),
\]

但这只是目标定义，不是我们已经有全局最优算法。执行前不知道哪些查询实际改变，也不知道改变后会发现哪些新调用。共享子图使成本不能简单逐根相加；细粒度证书维护、批量查询和一次性重建还会改变可行计划的成本结构。

局部可用的决策规则是：设精确校验成本为 \(k\)，校验后结果未变的概率估计为 \(p\)，若直接重算成本为 \(r\)，且校验失败不会降低重算成本，则先校验的估计成本为 \(k+(1-p)r\)。只有当 \(k<pr\) 时，它在这个简化模型下更便宜。若失败后可复用已查询的结果，必须用相应剩余成本替换 \(r\)，不能重复计费。

\(p\) 只用于决定先做哪个安全动作，**绝不能用于跳过验证并把旧值宣称有效**。预测失误只应造成多花时间，不能造成错误复用。概率与成本估计必须来自训练/历史运行，不从保留测试事件反推最优阈值。

建议先比较三个透明调度策略：固定精细校验；达到预设 watcher/候选扫描预算后整根重算；利用历史观测耗时作上述局部选择。重算前沿上的节点必须先得到新快照有效值；跨过一个 frontier 只意味着消费者可以读取这些值，不意味着未验证的路径可忽略。共享调用按稳定键仅计算一次，按需分支不得盲目按旧全图预执行。

最坏情况反例：每批全局策略变化都命中几乎所有 watcher，验证扫描/排序全部 N 个候选，随后大部分结果仍改变并必须调用模型。此时增量路径多付了扫描、证书和图维护成本。应允许整根重算回退；若下一轮还要增量复用，本轮仍要重建必要轨迹与订阅，其成本也不能隐藏。若选择完全退出增量模式，则不再声称保有未经重建的细粒度证书。

选择计划只承诺满足相同正确性条件，并实测成本；当前不承诺全局最小前沿、最少节点重算、最优在线竞争比，或相对全量重算的统一速度界。

## 8. RAG、Agent、SFT 如何进入同一语义

- **RAG**：工具查询、候选排序、内容投影是可追踪节点。冻结底座下，数据库更新引起回答变化，是检索/执行更新，不是模型学到了新事实。
- **Agent**：每次工具调用及控制决策都有公开输入；数据变化可导致新的查询参数和分支。动态扩边是执行中发现依赖，不能预先把所有“可能相关知识”说成已经覆盖。
- **SFT 数据**：每条样例保存来源快照、输入构造、目标规则/人工标注版本及其依赖证书。事件可使样例进入 `needs_revalidation`；重验证后的新训练集是新的不可变 manifest。不能在线修改已开始训练 epoch 的 labels，也不能只检查最终答案文字相同而遗漏引用和适用条件变化。
- **SFT 参数**：删除一条样例或重建训练集不等于从已有权重删除影响；本框架不提供 machine unlearning 保证。更新模型后，以新模型 revision 重算涉及该模型的节点；是否值得训练由独立行为退化诊断、保留能力与训练成本决定，不能由“数据库有变化”直接推出。

第一阶段应固定模型与工具比较 U1—U4。之后才比较固定模型、策略 SFT、每批事实 SFT 等学习路线，且保持知识快照、工具权限及评测时预算相同。研究边界是区分“知识新了”与“决策策略变好了”，不预设微调一定有价值。

## 9. 设计时提出的小规模判别验证

本节保留原先的判别逻辑。后续有限回放和成本实验已经执行；具体实现/未覆盖项以 [结果页](../docs/results.md) 为准，不能把本节全部建议自动升级为结果。

先做不依赖 LLM 的有限执行器检查，再加入真实本机模型；这样模型回答错误不会掩盖更新语义错误。

| 检验族 | 最小设置 | 区分什么 |
|---|---|---|
| 新候选/空查询 | 0—3 个候选，一次插入/删除 | U2 的结构性缺口，U3/U4 的 COVER |
| 适用谓词 | 同一发行文件跨 Python、extras、组织策略变化 | 仅内容引用与完整查询依赖的区别 |
| 观测不变 | 无关字段变更；域内新增但投影/选择不变 | U3/U4 是否有净成本差异 |
| 动态换支 | flag/A/B 两批更新 | 输出不变时是否丢失新依赖 |
| 同事务联动 | 两条互相关联记录原子更新；索引延迟/中途失败 | 发布一致性，不以最终收敛掩盖中途脏结果 |
| 生命周期 | 重复事件、缓存冷/热、模型/工具版本改变 | 隐藏输入、幂等性与真实维护成本 |

对有限小状态空间枚举合法状态与一/两步更新，逐步比较 U1/U3/U4 的公开输出、证书和订阅；U2 的失败应由预先定义的事件解释。集成模型后，独立报告结构合同有效率、任务正确率、重跑分歧和更新成本，不把“避免调用”自动计作“正确复用”。

**否定主线的对照**：若一个粗粒度的“项目域版本 + 普通 memo/early cutoff”基线，在同一正确性条件下达到相同或更低总成本，那么更复杂的适用谓词证书没有增量价值。若 U4 相对 U3 只有调用数优势、总时间或空间没有优势，只能报告调用节省，不能宣称更新更高效。

**重新展开条件**：COVER 无法实现、真实工具存在无法封装的隐藏输入、维护成本持续超过重算、或最近邻已完整覆盖候选差异时，保留失败记录，退回粗粒度正确实现；不以减少证书内容或放宽一致性门槛补救结果。

## 10. 与现有理论的关系

命题 A 的证明结构是纯函数/受控效应下的增量重跑一致性；命题 B 对应集合查询的 phantom/negative dependency；命题 C 对应动态依赖重建。全部都有经典理论背景。项目若形成贡献，应来自可复核的接口契约、任务边界和公平实验，而非将这些概念更名。具体已读证据、未读部分与不能声称的新颖性列于 [prior-work.md](prior-work.md)。

# DeltaWeave：反对意见、失效边界与可裁决反例

状态：2026-10-28 的研究审查与实验建议；不是已经完成的实验，也不是已冻结的验收协议。本文只讨论机制，不预设模型训练能解决缓存正确性。

## 1. 最强反对意见

“记录完整候选集、正负谓词依赖，固定快照，重新查询后 digest 相同就停止传播”在闭合、确定性的执行环境下是合理的增量计算方案。但**动态依赖、内容指纹和相等输出截断均已有成熟先例**。如果 DeltaWeave 的执行节点与依赖语义能完整翻译成经典构建系统，主张应是领域应用、语义合同及实证研究，不能称为新的通用增量算法。

真正待裁决的是两件事：第一，专业知识工具能否提供足够完整、仍然便宜的观测合同；第二，在包含建索引、建证书、失效传播和失败回退的总成本里，这种合同是否值得维护。只击败“仅跟踪旧引用”的弱基线不够。

## 2. 可以成立的窄保证

将一次节点计算写为 `y = f(code, model, prompt, decoder, environment, observations)`。若以下条件同时成立，输出不变后的安全复用可用依赖图上的归纳论证；这属于已有增量计算思想在此处的实例化。

1. 每个会影响节点行为的输入都通过可追踪接口进入，包括控制分支、空查询、工具模式、环境标记、时钟、权限与模型版本。只追踪答案引用不足以追踪计算。
2. 谓词证书相对于明确的关系域完整；插入、删除、修改、别名和规则更新均能保守触发相应查询。未知域不能被解释为空域。
3. 观测来自同一个可发布快照；数据、索引、策略及外部工具的版本合同一致。必要时等待、重启或返回不可确认。
4. digest 的相等语义涵盖下游可观察的全部内容；结构化集合可规范化，但若模型实际看到了排序、分数或文本，不能擅自把这些输入删出指纹。
5. 节点确定性成立，或缓存命中只承诺复用同一随机执行样本，不冒充与重新采样的输出相同。模型、adapter、模板和工具代码变化必须失效。
6. 重新执行产生的新依赖边，即使值相同，也必须原子替换旧依赖边；边更新先于对后续事件开放。

因此，不应说“上述所有条件满足后仍必然漏依赖”。下面的正确性反例主要检验条件是否真的被实现；成本反例则在这些条件全部满足时也成立。完整读集保证的是相对执行合同的一致性，不能证明语言模型对现实世界的理解正确。

快照编号和内容相等应分开：若把每次全库提交号直接放入所有节点的内容 digest，任何无关更新都会迫使全图失效；若完全丢弃版本信息，又可能混读。合适的结构是版本化证书负责证明“此次复用仍有效”，规范化的观测内容负责决定是否需要重新推理，公开答案的来源信息则独立刷新并检查。

## 3. 最小反例与工作负载

以下包名和策略均为拟议的合成例子，不代表任何真实软件漏洞。每个事件链必须有匹配的无关更新对照，不能只出会改变答案的题。

### C1：从空集出现新例外，导致新工具依赖

`v0`：P 的版本与 Python 条件都满足；查询“适用于 P、当前平台的例外”返回空集；模型尚未读取环境的 `ssl_abi`。`v1` 新增例外：“P 在当前平台必须满足 ssl_abi >= 3”。环境实际为 1。

正确更新必须先发现例外，再新增读取 `ssl_abi` 的依赖，最后改变结论。旧正依赖图没有这个新事实的边，必漏；空谓词观察可以触发它。将例外写成另一包的同样文本是负对照，答案应保持不变。若把例外检索限制为旧 top-k 文档并把“没检索到”当空集，仍可能漏。

裁决：记录是否取得例外及新环境事实、最终判断与引用；不能仅凭模型碰巧猜对结论判为新依赖发现成功。

### C2：值没变，证明与依赖却变了

`v0` 结论由来源 A 支持。`v1` A 被撤回，独立来源 B 提供相同值，结论保持。`v2` B 也被撤回，此时应不可确认。

若 `v1` 比较最终值相同后跳过依赖替换，`v2` 不会触发重算；若仍展示 A，`v1` 已经引用失效。反例不要求重新生成相同自然语言，只要求正确更新来源集合及后续触发关系。另加“双来源同时有效，撤回其中一个”的版本，避免把任何撤回都错误解释为结论失效。

裁决：整个三步链全对、来源有效、第二次撤回能触发；比较输出值 digest 与观测/证明 digest 的消融。

### C3：每个快照都不可行，混读却可行

`v0`：P 要求 Q2，但只有 Q1 可用。一次原子提交产生 `v1`：P 改为要求 Q1，同时 Q1 下架、Q2 上架。两个完整快照都不可行。

在读取 P 之后、读取 Q 之前注入提交。如果读到旧 P 与新 Q2，会错误判断可行。分别注入数据库提交、向量索引滞后、策略缓存滞后三种窗口。只在返回 JSON 里补一个 snapshot_id 没有证明作用；每次工具读取都需实际绑定相同已发布版本。

裁决：必须返回某个完整版本的正确结果，或明确重试/不可确认；不能把未完成任务算成功。固定注入点，不依赖偶然时序复现。

### C4：候选集未变，但决定适用性的域变了

版本查询始终返回 P1。新提交改变包级政策，或新增将 P 的旧名称归一到新政策范围的别名；版本候选集的值完全不变。若证书仅监听版本关系而没有政策、实体归一化和工具语义版本，便会错误复用。

这是完整性边界测试，不是声称任何谓词框架都无法解决。受支持域必须登记这些输入；未注册的模式/工具版本变化至少触发保守全量重算。针对任意自然语言例外无法证明域已闭合时，应标注证书为未认证，不能用 LLM 自报完整代替证明。

裁决：分别测试已声明政策变动和未知关系类型变动；前者必须被正确处理，后者必须失效回退。不要把“不支持的任意现实语义”伪装成基线错误。

### C5：时间前进、迟到修订与查询排序

一条政策到期，但期间没有新行写入；没有时钟/有效期事件的系统会一直复用旧答案。另一版本中，今天入库的更正追溯到过去生效；只依据 `valid_from` 的事件扫描会遗漏今天发生的修订。需要区分入库/事务时间与事实有效时间。

再将两份互相冲突的候选保留为相同 ID 集合，但改变权威等级或实际送入模型的排序。仅对 ID 集合取 hash 会错误命中。若接口事先保证按固定顺序提供完整结构，顺序可规范化；若模型实际输入不同，便不是同一观测。

裁决：过期无写入、追溯更正、权威变动、纯展示顺序变动分别计分，不把时间字符串本身当更新标签。

### C6：大扇出更新与完整证书的成本反转

所有问题都受同一全局政策影响。改变该政策会触发几乎所有 watcher；完整候选查询还可能扫描、排序、规范化并 hash 大量记录。即使最终需要的模型调用与全量重算一样多，增量系统仍多支付图维护成本。

扫描维度建议：无关记录数 `N ∈ {100, 1,000, 10,000}`、触发问题比例 `ρ ∈ {0, .01, .1, 1}`、每次变更后的重复读取次数 `R ∈ {1, 4, 16}`。这是待运行的 CPU 参数网格，不是已有结果；模型仅抽取固定小子集测实际耗时，不能拿人为注入的模型延迟当真实推理收益。

裁决：含首次构图和全部事件维护的累计时间、内存、扫描行数；寻找盈亏点。可使用仅在 dev 拟合的回退阈值，但全量基线同样享有批处理、索引和结果缓存。允许结果是“此负载不适合增量”。

### C7：没有复用，或当前请求只触及旧图的一角

每次都问新实体的新问题，或者后台维护一万个历史问题但下一次只访问十个。全图主动传播可能比按需从头执行更贵。比较 eager 与 lazy 调度；另记录后台维护成本，不能把它移出计时窗口。

裁决：冷启动、首次问题、重复问题分别报告；统计有多少维护工作在观察窗口内从未被任何请求使用。只有高复用场景获益时，贡献应限定于该场景。

### C8：结构化强规则已经足够

在有限版本、明确环境标记和确定冲突规则下，穷举或约束求解器可以准确判断兼容性。给它相同可见工具与预算，并用同样的通用依赖追踪维护结果。若它在正确性、成本上都不弱于 LLM，则本项目证明的是数据库/求解工程价值，不是 SFT 的必要性。

可以另外设置自然语言需求解释、跨文档指代和未见表达来测模型，但不能故意把普通规则基线限制成几个脆弱关键词。若封闭语法解析器已经覆盖全部真实任务，就应保留规则优先的产品路线。

## 4. 成本与“最小重算”的诚实边界

总成本至少计为 `初次构建 + Σ(入库/索引 + 事件匹配 + 证书检查 + 图维护 + 工具 + 模型 + 重试)`。只有当省下的执行成本超过证书及维护成本时，增量才盈利。相等检查本身可能需要完整读取；“模型调用少了”不能推出“系统更快”。

设 `A` 为经独立参考判定观测可能变化的节点集合，`F` 为算法重验证的集合。保守正确性希望 `A ⊆ F`；效率希望 `F` 小，却不意味着 `F` 达到全局最小。直接查看最终真值来选择重算集合会给算法 oracle 信息，不能作为可部署实现。图有环时也不能直接套 DAG 归纳；应声明本阶段只支持无环执行轨迹，或另给有界固定点/循环中止语义。

## 5. 路线保留与收束条件

| 待证明主张 | 最强挑战路线 | 收束或修订条件 |
| --- | --- | --- |
| 新增依赖得到正确发现 | 全量规则求解；完整集合/目录观察的经典 trace runner | 仅胜旧引用传播则不足；若与经典 runner 行为等价，明确降低算法新颖性主张 |
| 成本优于重算 | 带共享索引、缓存和批处理的完整重算；lazy 维护 | 高扇出、低复用持续亏损时保留回退，并报告适用区间 |
| SFT 提升更新能力 | 原始模型、证据条件 QA SFT、规则策略 | 同证据动作能力没改善，则不能把端到端增益归因于 SFT |
| 小模型适应未来变化 | 固定 adapter 的未见实体/组合/后续版本；证据替换反事实 | 只记住旧事实或模板时停止扩大“专业理解”结论 |

可争取的贡献是：把不完整语义检索与可认证结构化观察明确分开，给出可复现的复用失效反例、同预算成本曲线，以及训练收益的因果拆分。能否进一步形成算法贡献，要等对经典强基线的实质差异及实验结果，而不能先命名再论证。
